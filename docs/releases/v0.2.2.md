## Downloads and operation

Choose Python issued banking, Java issued banking, Java monthly banking or
scheduled marketing from the release assets. Verify the matching `.sha256` file
before extraction and follow the bundled README. The shared
`release-manifest.json` records the four archives, image identities and source
revisions; each archive includes its own file manifest. A source version does
not establish that release assets are available.

For an existing marketing installation, use the Java monthly-banking guide's
second-domain procedure. Do not rerun a fresh initializer over existing
connections or delete them to bypass its refusal. Finish active runs before
changing static connections and recreating Runtime. This procedure does not
provide automatic live registration or modify accepted runs.

Preserve platform database and evidence volumes, configuration and deployment
identity. Marketing domain and agency conversation state remain in memory.
These trusted single-host examples do not establish production isolation,
high availability or population capacity. Keep credentials and evidence private.
A completed simulation does not certify advice quality or execute a real payment
or campaign launch.

Published v0.2.1 and earlier archives retain their original bytes, image pins
and instructions. Use each archive's guide and manifest rather than replacing
its images with another version's selection. The online
[monthly-banking guide](https://astraform.ai/docs/starters/monthly-banking/#existing-platform)
also describes the additive route for unchanged v0.2.1 downloads.
