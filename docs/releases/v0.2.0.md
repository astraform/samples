Java author kit **0.4.3**, Python author kit **0.3.3** and contracts **1.2.1**.
Download a starter only after its release and matching platform are published.
Selecting a compatibility version is not proof that its artifacts are available.

Installed image dependencies must be verified separately from source pins.

## Existing integration and completion behavior

Customer creation, publication, launch, inspection and evidence export use the
native Java/Python SDKs. Banking preparation seeds only the partner-owned backend
and discovers the customer's scoped MCP grant; the existing downloaded Java
client then owns the Java customer workflow. A Java provider with a Python
customer does not demonstrate a Java customer launch.

Issued banking and scheduled marketing preserve their explicit
`completionPolicy.requireCustomerFinish:true` plus receipt conditions. Monthly
banking preserves its authored policy, native domain work and horizon; it does
not acquire a strict flag during packaging. No customer decision or model prose
is scripted, repaired or replaced. Inspect actual advice and stop reasons;
configured achievement does not certify factual quality or payment execution.

## Release preparation and limits

`release.json` stays `publicationReady:false` until all null revision, image and
checksum selections are replaced with reviewed real values. Build the five
sample image packages from the selected full source commit, verify anonymous
AMD64/ARM64 access and actual SDK contents, then prepare and test all four
archives against the released platform. Commit the reviewed selection separately
from the source that produced those artifacts. The existing release workflow
reproduces the approved hashes, verifies draft-uploaded bytes and refuses existing
tags/releases. Do not precreate or replace the samples tag.

The local-verification mode remains an explicitly marked engineering rehearsal;
it is not a public-release shortcut. Domain/customer code, scenario facts,
completion policies and model profiles are preserved by this packaging change.
Public archive/image accessibility, runtime checks of the actual published bytes,
the matching website Java downloads and independent operator acceptance remain
required. Image architecture descriptors alone do not prove runtime execution.

This is a single-host/private-network evaluation. No payment, campaign launch,
production security, HA or population-capacity claim is made. Marketing domain
and agency conversation state remain in memory; exported platform evidence is a
separate durability boundary. Keep credentials, logs and customer evidence private.
All Astraform-authored samples retain Apache License 2.0; platform software and
third-party dependencies retain their separate terms.
