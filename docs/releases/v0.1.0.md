# Astraform Samples v0.1.0

The first shared release of Astraform's public examples. All domains, languages
and frameworks use this repository version; choose the example you need without
installing the others.

## Included

- A downloadable **Python banking starter** and SHA256 checksum: prebuilt bank,
  separate PostgreSQL database, LLM Banking Advice agent, Gemini/Ollama templates,
  customer scenario and SDK launch/inspect/export helper.
- Source examples for Java/Spring banking, Python/FastAPI banking, Marketing Ops,
  the LLM Creative Agency, Banking Advice and Refund Policy.
- Guides for connecting partner services to the released Astraform platform
  through HTTP, A2A and customer-scoped MCP tools.
- Apache 2.0 licensing for all Astraform-authored examples and documentation.

Java and marketing are source examples in this release. Prepared starter
archives for them are not included yet. GitHub's source archives contain only
this public samples repository, not the Astraform platform implementation.

## Python banking starter

Avery has an already-issued January credit-card statement and AUD 100 available.
The customer must understand the amount, due date and whether that budget covers
the minimum payment or full balance. The customer reads its assigned account
through MCP; the banking partner reads the same backend through its own API and
answers over A2A. Both agents use configured language models.

Download `astraform-banking-starter-v0.1.0.tar.gz` and its matching `.sha256`
asset. Verify the checksum before extracting, then follow the included README.
The release also includes `release-manifest.json` with release and starter
provenance. The archive selects refreshed, digest-pinned Python SDK 0.3.2
banking and advice images; `bundle-manifest.json` records their actual build
revision, compatibility and payload hashes. Its embedded notes come from the
selected packaging revision, which can differ from the repository release commit.

## Compatibility

| Component | Version or requirement |
| --- | --- |
| Astraform Platform | **v0.2.0**, downloaded separately from [the platform release](https://github.com/astraform/releases/releases/tag/v0.2.0) |
| Python SDK | **0.3.2**, included in the Banking Advice image |
| Java SDK | **0.4.2**, used by the Java source examples |
| Public contracts | **1.2.0** |
| Starter host | Docker with Compose v2 and Python **3.10+** for initialization |
| Models | Gemini or Ollama, configured separately for the customer and partner |

Platform, SDK and samples versions are independent. Provider credentials remain
in local private configuration and are not part of the archives.

## Verification and limits

Source compatibility checks against the published Java 0.4.2 and Python 0.3.2
packages passed 621 banking, marketing and advice tests with no skipped tests.
Python banking used real PostgreSQL. Advice tests used owned HTTP/model fixtures;
these package checks did not execute a real customer-model simulation.

Earlier ARM64 reference trials used the released platform bundle and the previous
Python SDK 0.3.1 banking images. Gemini achieved the configured customer goal
with an MCP lookup and a real A2A partner exchange. The Ollama customer retrieved
its statement but abandoned the goal before contacting the partner; that run did
not exercise the partner model. Both outcomes and same-run evidence inspection
were preserved. Those trials do not establish the outcomes of the refreshed
images. Check the release's current verification record for the exact image
digests and actual model outcomes; AMD64/ARM64 availability alone is not runtime
verification on both architectures.

The packaged scenario uses fixed, already-issued records. It does not exercise
monthly statement generation, multiple customers or capacity limits. The banking
partner reads current records per request, has no persistent conversation history
and cannot make or schedule payments. Source examples include additional
scenarios; their presence does not extend this starter's verification.

Customer choices and goal failures are simulation evidence. Service health or a
successful export does not establish answer quality. Inspect the goal, messages
and actual tool activity in the result before evaluating the partner's behavior.
